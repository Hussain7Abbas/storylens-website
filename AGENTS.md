# Story Lens website instructions

Standalone public repository, also pinned in the Story Lens umbrella at `apps/website`.
Use Bun and Biome. Next.js App Router exports all pages statically; Nginx serves the export with no Node server. Commands are in `make help`.

- Use strict TypeScript, named exports except framework entries, no `any`, and no lint suppression comments.
- Use the Ink & Iris tokens from `design-system/MASTER.md`; visual values belong in `src/app/globals.css`. Inter supplies UI/headings, Cormorant only reading passages, and IBM Plex Sans Arabic for Arabic. Use Lucide outline icons at 1.75 stroke weight; keep semantic state and reader highlight colors separate. Three.js geometry is a documented decorative exception; its colors must follow the resolved tokens. Use the approved Lensbook logo (option 2). Its source, palette chart, icon exports, and regeneration instructions live in the umbrella `docs/branding/`. Website assets include 16/32px PNG and ICO favicons, a 180px Apple touch icon, and 192/512px manifest icons; retain accurate size metadata.
- Keep English and Arabic messages in `src/i18n/messages/`; update both. Use logical CSS properties and test RTL.
- Legal bodies live in `src/content/legal/{en,ar}` as MDX. Verify data claims against the source inventory, update both languages, version/date, and changelog together. Never infer third-party retention guarantees.
- Motion is optional. Respect reduced motion, render content before JavaScript, and keep Three.js lazy and absent on mobile or reduced motion.
- Run typecheck, Biome, build, Playwright/axe, and relevant Lighthouse checks. Record actual results; do not claim manual audits were done without evidence.
- Account pages under `/[locale]/profile/` render client-side, call the reader API (`/api/user/auth/*`, the website session under `/api/user/auth/web/*`; only the Google sign-in start uses Better Auth's `/auth/*`) at `NEXT_PUBLIC_API_URL`, and exchange the session with the extension through `src/lib/account/bridge.ts`, which must match the extension's `src/lib/website/account-bridge.ts`. The bridged user carries `isGuest`, `role` and `permissions`; `normalizeAccountUser` also accepts the older `role` string. Keep `autocomplete`/`name` hints on credential fields and keep the pages `noindex`. The website's own session is the API's HttpOnly cookie, sent with `credentials: "include"` and `X-Storylens-Web: 1` (`web: true` in `src/lib/account/api.ts`); JavaScript never stores a token, and bearer tokens only pass through the bridge to and from the extension. Pages render from the website session; the extension never blocks them. Keep `decide()`/`safeNext()` in `src/lib/account/reconcile.ts` pure and covered by `tests/account-reconcile.spec.ts`, and run automatic reconciliation one step at a time, at most once per state pair. Defer handoff during sign-in redirects and on the OAuth callback to the destination page. A `?reauth=1` account visit requests a fresh extension bearer session for the same account; carry only the renewal flag through sign-in redirects in `sessionStorage`, consume it before the bridge updates, and retain the account-choice prompt when the accounts differ.
- Lenses: the balance page (`/[locale]/profile/balance/`) and every billing call use the website session; prices and limits come only from `GET /api/user/billing/pricing`, never hard-coded in pages; money goes through `src/lib/billing/money.ts` (integer micro-dollars, the API's rounding) and contacts through `src/lib/billing/contact.ts` (the API's rules). Show prices only with `LensPrice`/`LensCoin` in `src/components/billing/`. Confetti (`canvas-confetti`) loads only when a gift exists and never with reduced motion; notices are marked seen with `surface=website` only.
- Keep balance snapshots tagged with their account ID. Switching accounts clears the previous account's balance while fetching, remounts the billing page and gift celebration, and clears the old account's notice; never reuse request history or an acknowledged gift dialog across accounts. `tests/account.spec.ts` covers an account switch while the new balance response is delayed.
- `LensCoin` keeps the original full/small/mono SVG fixed and adds three CSS sparkles through `src/lib/lens-coin/LensCoinSparkles.tsx`. They brighten at 300 ms offsets (900 ms per sparkle), using theme iris or `currentColor` for mono, with fixed layout and decorative accessibility. Containing-control hover/focus pauses the sparkle opacity; reduced motion and forced colors hide the decorations. Mirror the component and global styles from umbrella `docs/branding/lens-coin/`; no animation player, timers or remote assets. `tests/lens-motion.spec.ts` checks staggered lighting, static artwork and reduced-motion changes.
- `deploy/security-headers.ts` hashes static inline scripts after each export; never deploy pages with headers from a different build. `deploy/nginx-csp.ts` splits the policy into bounded Nginx variables and joins them into one header, avoiding the parser's 4096-byte parameter limit as the export grows. Keep all hashes and the restrictive script policy; `tests/security-headers.spec.ts` checks large policies and actual exported hashes.
- Google Analytics 4 lives in `src/lib/analytics.ts` and `src/components/layout/AnalyticsConsent.tsx`, enabled only when `NEXT_PUBLIC_GA_MEASUREMENT_ID` is set at build time (which also adds Google origins to the CSP). gtag.js loads only after the visitor clicks "Allow analytics"; keep decline equal in prominence to accept, advertising consent denied, Google Signals off, and `page_location` stripped of query and fragment. Send events through `trackEvent` with snake_case GA4 names (prefer recommended events such as `login`, `sign_up`), never PII; mark install CTAs with `data-analytics-cta`. Any change to collected data updates the privacy MDX in both languages and `design-system/data-inventory.md`. The `.claude/skills/analytics` skill (MIT, coreyhaines31/marketingskills) holds tracking-plan guidance.
- The landing page shows real extension screenshots in `public/images/extension/`, with English/Arabic and light/dark variants. Refresh all twelve glossary/form/selection captures when those views change; use isolated sample data, optimized WebP, meaningful localized alt text, and lazy loading. The screenshot theme follows the website theme.
- `ReadingShowcase` adds contextual reading captures in `public/images/reading/` and local walkthroughs in `public/videos/extension/`. Keep five screenshots per locale, 640/1280px WebP variants, clean MP4 recordings, WebVTT captions, and the six-step text transcript synchronized. The website MP4s come from the raw capture video without the Chrome Store burn-in; they retain the original light extension theme. The top-center captions use a dimmed blurred panel, fade over 0.45 seconds at each cue boundary, and show immediately with reduced motion. Keep native WebVTT captions available if JavaScript is off or the viewer enables native captions; avoid duplicate on-screen text. Use native video controls, `playsInline`, `preload="none"`, no autoplay, and the native screenshot dialog with Escape and focus return. Screenshot links must still open the image without JavaScript. The umbrella source assets and capture/export instructions live in `docs/chrome-store/`.
- Server checkout: `/srv/storylens-website` on `ssh raseen`, release commits from `main` (the deploy workflow checks out the exact pushed main commit). Manual deployment uses `make sync`; it installs with Bun, builds, swaps a release symlink, validates Nginx, and reloads. The API is a separate repository.
- Keep old releases for rollback; never remove an active release. Public contact/legal decisions require the owner’s review before first publication.

- `.github/workflows/deploy.yml` is the only workflow; there is no CI quality workflow. Every push to `main` (or a manual dispatch on `main`) sends that exact SHA through a restricted SSH key, and the server rebuilds the site. It runs no typecheck, lint, Playwright, or Lighthouse checks. `DEPLOY_ENABLED=true` is a repository variable; production environment secrets are `DEPLOY_HOST`, `DEPLOY_PORT`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. Server SSH uses `/usr/local/lib/storylens/ci-ssh.sh`, installed from `deploy/ci-ssh.sh`, to validate and serialize checkouts. Never upload an unrestricted personal SSH key.
