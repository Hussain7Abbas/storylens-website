# Story Lens website instructions

Standalone public repository, also pinned in the Story Lens umbrella at `apps/website`.
Use Bun and Biome. Next.js App Router exports all pages statically; Nginx serves the export with no Node server. Commands are in `make help`.

- Use strict TypeScript, named exports except framework entries, no `any`, and no lint suppression comments.
- Use the Ink & Iris tokens from `design-system/MASTER.md`; visual values belong in `src/app/globals.css`. Inter supplies UI/headings, Cormorant only reading passages, and IBM Plex Sans Arabic for Arabic. Use Lucide outline icons at 1.75 stroke weight; keep semantic state and reader highlight colors separate. Three.js geometry is a documented decorative exception; its colors must follow the resolved tokens. Use the approved Lensbook logo (option 2). Its source, palette chart, icon exports, and regeneration instructions live in the umbrella `docs/branding/`. Website assets include 16/32px PNG and ICO favicons, a 180px Apple touch icon, and 192/512px manifest icons; retain accurate size metadata.
- Keep English and Arabic messages in `src/i18n/messages/`; update both. Use logical CSS properties and test RTL.
- Legal bodies live in `src/content/legal/{en,ar}` as MDX. Verify data claims against the source inventory, update both languages, version/date, and changelog together. Never infer third-party retention guarantees.
- Motion is optional. Respect reduced motion, render content before JavaScript, and keep Three.js lazy and absent on mobile or reduced motion.
- Run typecheck, Biome, build, Playwright/axe, and relevant Lighthouse checks. Record actual results; do not claim manual audits were done without evidence.
- Account pages under `/[locale]/profile/` render client-side, call the API at `NEXT_PUBLIC_API_URL`, and exchange the session with the extension through `src/lib/account/bridge.ts`, which must match the extension's `src/lib/website/account-bridge.ts`. Keep `autocomplete`/`name` hints on credential fields, keep the pages `noindex`, and never persist the session token in website storage.
- `deploy/security-headers.ts` hashes static inline scripts after each export; never deploy pages with headers from a different build.
- The landing page shows real extension screenshots in `public/images/extension/`, with English/Arabic and light/dark variants. Refresh all twelve glossary/form/selection captures when those views change; use isolated sample data, optimized WebP, meaningful localized alt text, and lazy loading. The screenshot theme follows the website theme.
- Server checkout: `/srv/storylens-website` on `ssh raseen`, release commits from `main` (CI checks out the exact tagged commit). Manual deployment uses `make sync`; it installs with Bun, checks, builds, swaps a release symlink, validates Nginx, and reloads. The API is a separate repository.
- Keep old releases for rollback; never remove an active release. Public contact/legal decisions require the owner’s review before first publication.

- `.github/workflows/deploy.yml` deploys `v*` tags only after verifying the commit is an ancestor of `origin/main` and passing quality checks. It deploys that exact SHA through a restricted SSH key. `DEPLOY_ENABLED=true` is a repository variable; production environment secrets are `DEPLOY_HOST`, `DEPLOY_PORT`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. Server SSH uses `/usr/local/lib/storylens/ci-ssh.sh`, installed from `deploy/ci-ssh.sh`, to validate and serialize checkouts. Never upload an unrestricted personal SSH key. Manual dispatch uses the same ancestry and quality gates.
